# Measured baseline and candidate comparison

Purpose: interpret the recorded baseline experiment. These are historical results, not current serving quality or a fresh evaluation. Reproduce with the [baseline workflow](../README.md#run-the-example-locally); use [observability](observability.md) for explicit observation verification.

Executed on 2026-10-05 with the locked environment (Python 3.13.14), archived GFS fixed-offset forecasts and NZWN routine METAR observations. Exact metrics, ranges, candidate validation scores and input hashes are in [results.json](results.json). The following table is generated by the evaluation code.

The validation-selected mean-bias correction improves test RMSE by **17.7%** (1.458 → 1.200 °C), with MAE 0.893 °C and bias +0.002 °C. Ridge and XGBoost improve raw test RMSE by 23.3% and 23.1%, respectively. They do not beat the simpler correction on validation, so test results do not override selection. `model.joblib` contains the selected correction; `ridge.joblib` and `xgboost.joblib` preserve the fitted candidates.

17,099 of 17,544 requested hours matched (97.46% coverage); matched reports were exactly on the hour. Usable training pairs begin 2024-01-19 12:00 UTC. No gaps were filled. The two temporal embargoes remove a further 96 hours from modeling.

Saved-model reload checks passed for both ML candidates and the selected method. Repeated offline runs against the same cache produced identical metrics JSON, test prediction CSV and metadata JSON. Eleven automated checks cover metric signs/invalid inputs, split embargoes, feature independence from observations, insufficient splits, nearest-report preprocessing/QC, config leakage rejection, deterministic training, hashing/reload and invariance of model selection to changed test targets.

The documented `uv run --locked meteo-baseline run` also passed in a fresh source directory with no virtual environment, data cache or artifacts. It downloaded all four responses and reproduced every split metric and validation selection. Upstream response hashes can differ between downloads even when forecast values agree.

The ridge holdout was inspected before adding XGBoost. This expanded comparison is exploratory and limited to one station and one half-year test. A fresh future holdout is needed for independently confirmed selection gains.
